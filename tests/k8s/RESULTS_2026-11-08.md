## Test design

* Namespaces used: `ai-ticket-summarizer` (from the example), `saf-test-client` (test fixture) and `ai-gateway` (stand-in gateway). The allow rule selects the gateway namespace by its immutable `kubernetes.io/metadata.name` label, so the stand-in has to live in a namespace named `ai-gateway`.
* Stand-in gateway: `nginxinc/nginx-unprivileged:1.29-alpine`, pod label `app=ai-gateway`, listening on 8443 (should be allowed) and 8080 (should stay blocked). Plain HTTP on 8443 is enough to test the network path.
* Client: `curlimages/curl:8.17.0`, restricted-compliant, ServiceAccount `uc-0001-summarizer`.
* Policies are applied in stages: namespace + SA, then pods, then **positive controls**, then default deny, then the allow rule. So every "blocked" result is shown to be caused by the policy, not by a path that never worked.
* Every "blocked" result below is a timeout (curl exit 28 or nslookup "connection timed out"), not some other error.
* The script refuses to run if any of the three namespaces exists, and deletes only namespaces labelled `saf-test=true`.

### Finding S2.1: the documented validation command fails on a fresh cluster

`baseline/README.md` says to validate with `kubectl apply --dry-run=server -f baseline/examples/`. A server-side dry run does not persist the namespace, so the three namespaced objects fail with `NotFound` unless `ai-ticket-summarizer` already exists. The YAML is correct (S2.2, S2.3, S3.x). This needs a documentation fix, not a manifest fix: dry-run the namespace, create it, then dry-run the rest.

## Limits of this test

* Single-node cluster: pod-to-pod traffic did not cross nodes. NetworkPolicy behaviour across nodes was not tested.
* IPv4 egress was tested. IPv6 egress was not (the client resolves AAAA records, but the cluster is IPv4 single-stack).
* The stand-in gateway is plain HTTP on 8443. TLS and hostname allowlisting in a real gateway are out of scope; NetworkPolicy cannot enforce hostnames.
* Results with other CNIs (Calico, Cilium, ...) may differ in edge cases, for example how named ports or hostNetwork pods are handled.
